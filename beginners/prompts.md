# 可复制的提示词模板

把方括号内容替换为当前任务信息。模板能帮助交代要求；结果仍需回到材料逐项检查。初次使用时，搭配[练习素材](exercises/01-first-request.md)操作。

## 任务交代

```text
我要完成：[具体任务]
结果给谁看：[对象和用途]
已有材料：
[粘贴材料，保留编号]
必须保留：[数字、期限、状态或措辞]
限制：[字数、预算、可用时段等]
输出形式：[表格、邮件、提纲等]
只根据材料写；缺失的信息标“待确认”，建议单独标出。
先检查有没有会影响结果的缺失或冲突，再给出草稿。
```

## 从材料提取事实

```text
根据下面材料，输出“事实、来源编号、原文、需要确认的内容”四列。
区分计划、建议和已确认事项，不把缺失信息补成事实。
材料：[粘贴材料]
```

## 会议行动项

```text
从记录中提取任务、负责人、期限和来源编号。
负责人或期限未分配时写“待确认”。
把讨论过但未作决定的事项另列一表，不自行分配任务。
记录：[粘贴记录]
```

## 文件问答

```text
只依据下面文件回答问题。
每个答案先给条款号和逐字引文，再解释它能支持什么结论。
无法从原文确认的部分写“材料不足”，并说明应补充什么。
文件：[粘贴带编号的文本]
问题：[逐条列出]
```

## 改写而不改变事实

```text
把草稿改成适合[收件人/读者]的[邮件/短消息/周报]。
保留全部数字、日期、条件和未确认状态，不添加成绩或承诺。
长度约[字数]；改写后列出你对事实或语气有疑问的句子。
草稿：[粘贴]
```

## 比较方案和计算费用

```text
先列必须满足的条件，再比较方案。
费用逐项列公式和合计；条件不满足的方案标明原因。
把建议、前提条件和已确认事实分开。
材料：[粘贴方案与预算]
```

## 审查一份回答

```text
逐项对照原始材料和待审稿，检查数字、日期、引用、状态与遗漏。
输出“待审句子、依据、问题、修改建议”四列。
没有问题也要给出依据；不要为了凑数量编出问题。
原始材料：[粘贴]
待审稿：[粘贴]
```

## 针对错误进行追问

```text
这次回答中的[具体位置]与材料[编号]不一致。
请按[正确约束]修改相关部分，并检查表格、正文和结论是否同步。
其他仍正确的部分保留。另列出你无法从材料确认的信息。
```

可用[小样本评估](evaluation.md)比较修改前后的模板。想系统学习，可阅读[5 天提示词工程零基础](https://zhurilab.com/learn/prompt-engineering-5days)。返回[学习路线](README.md)。
